# Спека: v8-legacy-runner — дельта над апстримом для платформ 8.3.12–8.3.23

- Дата: 2026-11-06
- Статус: на ревью
- Репозиторий: `C:\w\v8-runner-rust` (форк `Asmody/v8-runner-rust`, целевое имя `Asmody/v8-legacy-runner`)
- Апстрим: `IngvarConsulting/v8-runner-rust`
- Согласовано в диалоге: подход A (зеркало + rebase-дельта), допущения приняты

## 1. Контекст

Проект УТ10 работает на платформе 8.3.12.1685 ежедневно. Апстрим решил поддерживать
платформы от 8.3.24 (PR #520, `MINIMUM_PLATFORM` + именной отказ
`INV.PLATFORM.A-PLATFORM-BELOW-THE-MINIMUM-IS-REFUSED`): у раннера нет частичной
загрузки ниже 8.3.24, а незнакомая команда платформы может не отказать, а зависнуть.
Наш PR #503 (фикс зависания зонда `/GetConfigGenerationID` на 8.3.12) закрыт без
слияния — правильно: апстрим не будет поддерживать старые платформы.

Нам нужна поддержка 8.3.12 при возможности обновляться из апстрима. Существующий фикс
лежит тремя коммитами (`680b6f8`, `43fe531`, `a94a86a` в ветке
`fix/generation-probe-old-platforms`) inline в файлах апстрима — эта форма не
масштабируется на долгую серию обновлений.

## 2. Цели и не-цели

**Цели:**

1. Поддержка платформ 8.3.12–8.3.23: обмен (push/pull/apply/reset/status) работает,
   зонд поколения не зависает, несверенность поколения видна.
2. Дельта над апстримом, накладываемая на каждый его апдейт с минимальными усилиями.
3. Регламентированная процедура обновления из апстрима, зафиксированная в правилах
   проекта.
4. Идентичность `v8-legacy-runner`, отделяющая наш бинарник и нашу линию версий от
   апстрима.

**Не-цели:**

1. PR апстриму — только по реальной необходимости (кандидаты отдельным решением).
2. Поддержка платформ ниже 8.3.12.
3. Изменения CLI, флагов и формата `v8project.yaml`.

## 3. Принятые решения (из диалога)

- **Подход A:** `master` — зеркало апстрима (только fast-forward), дельта —
  переосновываемая ветка `legacy/8.3.12`.
- **Несверенное поколение на 8.3.12:** громкое предупреждение, обмен не отказываем.
  Отказ при таймауте зонда на платформе, которая команду знает, — за апстримом; если
  апстрим его сделает, дельта унаследует автоматически.
- **Идентичность:** полное переименование (репо, пакет, бинарник), CLI без изменений.
- **Синхронизация с апстримом:** по требованию + еженедельная CI-проверка.

## 4. Архитектура дельты

### 4.1 Ветки

| Ветка | Что это | Правила |
| --- | --- | --- |
| `master` | зеркало `upstream/master` | только `merge --ff-only`; своих коммитов нет никогда |
| `legacy/8.3.12` | `master` + дельта-коммиты | здесь вся работа, релизы и спеки; обновляется rebase |

Теги: `legacy/v<версия>` (например, `legacy/v0.16.0-legacy.1`).

### 4.2 Новые файлы — всё знание здесь

Новые файлы не конфликтуют с апстримом никогда — в них живёт всё знание дельты:

```
src/legacy/
├── mod.rs         — таблица швов (§4.3) и назначение модуля; канонический перечень
│                    «что наложить при обновлении»
├── generation.rs  — GENERATION_ID_FIRST_PLATFORM (8.3.20), knows_generation_id(),
│                    PROBE_CAP (30 с) — переезжает из platform/generation.rs и
│                    generation_reader.rs
└── floor.rs       — LEGACY_MINIMUM_PLATFORM (8.3.12) и его толкование
```

### 4.3 Швы — изменения в существующих файлах апстрима

Правило шва: в файлах апстрима допустимы только вызовы `crate::legacy::*` и значения
констант; никакой логики inline. Каждый шов — 1–5 строк в стабильном месте.

| # | Файл апстрима | Шов | Объём |
| --- | --- | --- | --- |
| 1 | `platform/generation.rs` | наша правка убирается: `knows_generation_id` и порог переезжают в `src/legacy/generation.rs`; файл возвращается к виду апстрима | −33 строки |
| 2 | `platform/designer.rs::config_generation_id` | precheck: `if let Some(answer) = legacy::generation::designer_precheck(&self.binary) { return Ok(answer); }`; плечо `Err(DesignerError::Spawn(ProcessError::TimedOut { timeout_ms, .. }))` → `warn!` + `Ok(None)` | ~8 строк |
| 3 | `platform/ibcmd.rs::config_generation_id` | то же | ~8 строк |
| 4 | `use_cases/generation_reader.rs` | `Some(legacy::generation::PROBE_CAP)` вместо `None` | 1 строка |
| 5 | `platform/locator.rs::MINIMUM_PLATFORM` | значение 8.3.24 → 8.3.12; отказ апстрима `BelowMinimumPlatform` начинает работать на нас; комментарий ссылается на `src/legacy/floor.rs` | ~3 строки |

Состояние на 2026-11-06 (master `9b6c5d8`, апстрим +16 коммитов от точки форка):
пробное слияние дельты — **0 конфликтов**; `config_generation_id` обоих DSL апстрим не
менял.

### 4.4 Несверенное поколение — видно везде (замечания ревью #503)

Требование: на платформах 8.3.12–8.3.19 обмен идёт, но несверенность поколения видна
потребителю, а не теряется:

1. Причины «нет ответа» различаются в `src/legacy/generation.rs`: платформа без
   команды / снят по пределу / прочее. В журнал: `warn!` (снят по пределу — уже
   сделано), `debug!` (нет команды — уже сделано).
2. В выводе команд: `status --deep` дополняет reason несверенности
   (`status.rs:262`, `status.rs:577` — точки уточнения); при загрузке (push/apply)
   предупреждение «поколение не сверено» выводится на всех маршрутах исполнителя,
   включая `guarded_load` — major-замечание CodeRabbit к #503. Точки вывода сверить
   с новым механизмом апстрима `destruction_guard::unanswered` (появился в
   `9b6c5d8`) при переложении дельты; конкретные места — в плане работ.

## 5. Идентичность

- Репо: `Asmody/v8-legacy-runner` (GitHub оставит редирект со старого имени).
- Пакет и бинарник: `v8-legacy-runner` / `v8-legacy-runner.exe`.
- Версия: `<версия апстрима>-legacy.<N>`, например `0.16.0-legacy.1`; N растёт в
  пределах одной версии апстрима и обнуляется при каждом обновлении из апстрима.
- `FORK_NOTICE.md` переписывается: назначение — платформы 8.3.12–8.3.23, дельта
  поверх апстрима, ссылка на процедуру обновления.
- `README.md` — преамбула о легаси-назначении форка.
- CLI, флаги, конфиги — без изменений; локальный деплой — `C:\tools\v8-legacy-runner\`;
  `docs/memory/proc.md` проекта УТ10 обновляется при смене пути/имени бинарника.

## 6. CI

`.github/workflows/legacy-upstream-check.yml`: еженедельный cron —

1. fetch `upstream`;
2. `git merge-tree --write-tree master legacy/8.3.12` (или пробный rebase в worktree);
3. конфликт или новое движение апстрима → issue в форке со сводкой.

Никаких auto-push, auto-rebase, auto-merge. Существующие CI-проверки форка работают на
`legacy/8.3.12`.

## 7. Процедура обновления из апстрима (зафиксировать в правилах проекта)

Канонический текст процедуры размещается:

- в `AGENTS.md` — раздел «Легаси-дельта над апстримом» (кратко, с отсылками);
- в `src/legacy/mod.rs` — таблица швов (§4.3) рядом с кодом.

Шаги:

1. `git fetch upstream`
2. `git checkout master && git merge --ff-only upstream/master && git push origin master`
3. `git checkout legacy/8.3.12 && git rebase master`
4. Конфликты — только в швах, перечень в `src/legacy/mod.rs`. Шов правится, логика
   inline в файлы апстрима не возвращается. Если апстрим изменил затронутое швом
   место (например, взял предел или переустроил зонд) — апстрим-версия сильнее:
   конфликт разрешаем в её пользу и пересаживаем шов, при необходимости шов
   упраздняется.
5. `cargo fmt && cargo clippy --all-targets && cargo test`
6. `Cargo.toml`: `version = <версия апстрима>-legacy.<N+1>`
7. `cargo build --release`; тег `legacy/v<версия>`; деплой exe в
   `C:\tools\v8-legacy-runner\`; при изменениях CLI — обновить
   `docs/memory/proc.md` УТ10.
8. `git push --force-with-lease origin legacy/8.3.12`

Правила дисциплины:

- в `master` не коммитить никогда — всё (код, спеки, документация) в `legacy/8.3.12`;
- новое знание дельты — только в `src/legacy/`; при соблазне положить логику в файл
  апстрима — расширять шов нельзя, добавлять в `src/legacy/` можно;
- правка, требуемая в файле апстрима и полезная апстриму, — кандидат в PR апстриму;
  до принятия она живёт как шов.

## 8. Тесты и правила

- Тесты дельты переносятся целиком, но их судьба различна: тесты знаний
  (`a_platform_older_than_8_3_20_knows_no_generation_command`) переезжают в
  `src/legacy/generation.rs`, чеки правил обновляются на новые пути; тесты швов
  (TimedOut-плечо в designer.rs/ibcmd.rs, капа в generation_reader.rs) остаются в
  файлах апстрима — их адреса в чеках правил не меняются.
- Новые: пол 8.3.12 — 8.3.12 проходит `refuse_below_minimum`, 8.3.11 получает
  `BelowMinimumPlatform`; reason-строки несверенности в выводе.
- Правила `spec/rules`: наши
  `INV.PLATFORM.A-PLATFORM-WITHOUT-THE-GENERATION-COMMAND-IS-NOT-ASKED` и
  `INV.USE-CASES.A-GENERATION-READ-DECLARES-ITS-OWN-CAP` остаются; чек, указывающий
  на тест знания, обновляется на `src/legacy/generation.rs`, остальные чеки остаются; правило апстрима
  `INV.PLATFORM.A-PLATFORM-BELOW-THE-MINIMUM-IS-REFUSED` остаётся с нашим значением
  минимума (8.3.12).
- `references/1c/` — замер 03.11.2026 (8.3.12) остаётся, пополняется при новых
  замерах на легаси-платформах.

## 9. Миграция (разовая, порядок работ)

0. ✅ Процедура обновления из апстрима выполнена до изменений кода: `master`
   fast-forward до `9b6c5d8` и запушен; пробное слияние дельты — 0 конфликтов.

2. Создать `legacy/8.3.12` от нового `master`; переложить 3 коммита дельты в форму
   швов (§4.2–4.3): `src/legacy/` создаётся, inline-правки сжимаются до швов.
3. Закрыть PR #1 в форке (его ветка `fix/generation-probe-old-platforms` уходит,
   содержимое переложено); ветку удалить.
4. Переименовать пакет/бинарник; переписать `FORK_NOTICE.md`, преамбула `README.md`.
5. Добавить CI-workflow (§6) и раздел в `AGENTS.md` (§7).
6. Собрать релиз `0.16.0-legacy.1`, задеплоить в `C:\tools\v8-legacy-runner\`,
   обновить `docs/memory/proc.md` УТ10.
7. Прогнать живую проверку на базах УТ10 (`origin`, `test`): `status --deep`,
   `push Тесты --force` — без зависаний, предупреждения о несверенности видны.

## 10. Риски

| Риск | Ответ |
| --- | --- |
| Апстрим меняет `config_generation_id` или убирает | шов переносится по таблице швов; усилие мало |
| Апстрим принимает предел/гейт в своей форме | конфликт разрешаем в пользу апстрима, шов упраздняется |
| Локатор перестанет парсить версию из пути | `knows_generation_id` деградирует к «спрашиваем»; защищено `PROBE_CAP` |
| Дельта растёт и вгрызается в файлы апстрима | дисциплина §7; таблица швов в `src/legacy/mod.rs` — живой контроль размера |
| Отчёт о несверенности расходится с механизмами апстрима (`destruction_guard`) | при переложении сверить с апстримом; механизм апстрима сильнее |
